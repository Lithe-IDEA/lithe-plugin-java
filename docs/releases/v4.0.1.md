# Java 4.0.1

## 中文

改进 JDT LS 运行时 JDK（`jdtls-runtime`）的自动发现与启动前版本校验（[#27](https://github.com/Lithe-IDEA/lithe-plugin-java/issues/27)）。

### 修复与改进

- **`jdtls-runtime` 跳过 `PATH` 上的低版本 Java**：`jdtls-runtime` 的版本识别不再匹配 Java 8/11/17/20，避免 `PATH` 上的旧版 `java` 抢占已安装的高版本 JDK；未找到满足要求的系统 JDK 时仍保持明确报错，项目自身的 JDK 工具（`java`）不受影响。
- **自动发现 VS Code / Cursor `redhat.java` 扩展自带的 JRE**：将 `.vscode/extensions/redhat.java-*/jre/*` 与 `.cursor/extensions/redhat.java-*/jre/*` 纳入 `jdtls-runtime` 发现路径。
- **按目标 JDT LS 实际要求的 Java 版本校验并优选**：从目标 JDT LS 核心 bundle 的 `META-INF/MANIFEST.MF` 读取实际最低 Java 版本（例如 JDT LS 1.61 为 21，1.63+ 为 25）；自动发现时优先选择当前 `jdtls-runtime` 可运行的安装，不满足时在启动进程前直接给出准确所需的 JDK 版本提示（`launch.runtime_too_old`）。

### 兼容性

与 4.0.0 相同，**需要声明 `sourceSettings` 1 的 Lithe 宿主**。

---

## English

Improve `jdtls-runtime` discovery and pre-launch Java version validation for Eclipse JDT LS ([#27](https://github.com/Lithe-IDEA/lithe-plugin-java/issues/27)).

### Fixes & Improvements

- **Skip older Java binaries on `PATH` for `jdtls-runtime`**: `jdtls-runtime` version matching now requires Java 21 or newer so an older `java` on `PATH` (such as Java 8, 11, or 17) no longer shadows discovered JDK 21+ installations. The project `JDK` tool (`java`) continues to support Java 8+.
- **Discover JREs bundled in VS Code / Cursor `redhat.java` extensions**: add `.vscode/extensions/redhat.java-*/jre/*` and `.cursor/extensions/redhat.java-*/jre/*` to `jdtls-runtime` discovery.
- **Validate against each JDT LS installation's required Java release**: inspect core JDT LS bundle `META-INF/MANIFEST.MF` headers (`Bundle-RequiredExecutionEnvironment` / `Require-Capability`) to determine the minimum required Java version (e.g., 21 for JDT LS 1.61, 25 for JDT LS 1.63+), prefer a runnable installation during automatic discovery, and report the exact required JDK version before launch (`launch.runtime_too_old`).

### Compatibility

Same as 4.0.0: **requires a Lithe host advertising `sourceSettings` 1**.
